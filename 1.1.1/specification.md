#### 2. Thread types:
- `Event loop thread`: AKA `FastThreadLocalThread` in Netty.
- `Platform thread`.

#### 3. Threads count:
- `32` threads, which equals to 2 × 16 cores, aligned with the default configuration commonly used in production env.

#### 4. Java:
- `OpenJDK-21.0.11`.

#### 5. JVM args:
- `-XX:InitialRAMPercentage=40.0 -XX:MaxRAMPercentage=40.0`

#### 6. Data:
- `SOCKET_PROXY`: Generated by [WebSocketProxyPattern.java](https://github.com/neoionet/netty-allocator/blob/1.1/benchmark/src/main/java/io/github/neoionet/netty/microbenchmark/data/WebSocketProxyPattern.java), the data was copied from netty's [AllocationPatternSimulator](https://github.com/netty/netty/blob/4.2/microbench/src/main/java/io/netty/buffer/AllocationPatternSimulator.java#L53), which derived from a web socket proxy service.
- `API_GATEWAY`: Generated by [ApiGatewayPattern.java](https://github.com/neoionet/netty-allocator/blob/1.1/benchmark/src/main/java/io/github/neoionet/netty/microbenchmark/data/ApiGatewayPattern.java), which generates sizes based on a log-normal distribution, which is commonly used to model network traffic patterns, the median size ≈ 2 KiB; the mean size ≈ 3.3 KiB; the P95 ≈ 10KiB; the P99 ≈ 20 KiB, the sizes are constrained to be between 8 bytes to 1 MiB.

#### 7. Benchmark code:
- [ByteBufAllocatorAllocPatternBenchmark.java](https://github.com/neoionet/netty-allocator/blob/1.1/benchmark/src/main/java/io/github/neoionet/netty/microbenchmark/ByteBufAllocatorAllocPatternBenchmark.java).

#### 8. Code base:
- Netty-4.2.16.Final-SNAPSHOT, which compiled based on [ec4efdb](https://github.com/netty/netty/tree/ec4efdbbeebf024b64e0fb782184989835c9ab92).
- [Netty-allocator-1.1.1.Final](https://github.com/neoionet/netty-allocator/releases/tag/1.1.1.Final).

#### 9. Max live buffers per thread: 
- `MAX_LIVE_BUFFERS`: [128, 1024, 4096, 8192, 16384, 32768, 65536].
- Heap allocations skipped `65536`, as the pooled allocator threw `OOM` when `MAX_LIVE_BUFFERS` reached `65536`.

#### 10. Switch on read-write: 
- `enableReadWrite`: Enables read and write on each buffer to simulate real-world usage.
